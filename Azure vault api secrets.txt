A) Azure side (once per secret)

1. Create the secret in your vault
   az keyvault secret set \
     --vault-name tslvault \
     --name "MY-NEW-API-KEY" \
     --value "<your-real-value-here>"
   Or in the Portal: Key Vault › Secrets › + Generate/Import › enter Name and Value.

2. Grant your App Service’s managed identity access
   VAULT_ID=$(az keyvault show --name tslvault --query id -o tsv)
   APP_ID=$(az webapp show -g <rg> -n <app> --query identity.principalId -o tsv)
   az role assignment create \
     --assignee $APP_ID \
     --role "Key Vault Secrets User" \
     --scope $VAULT_ID

B) App configuration (Program.cs, only once)

Add this once at the top of Program.cs:

using Azure.Identity;
using Azure.Extensions.AspNetCore.Configuration.Secrets;

var builder = WebApplication.CreateBuilder(args);
var vaultUri = new Uri("https://tslvault.vault.azure.net/");

// Only register Key Vault when NOT in CI
if (string.IsNullOrEmpty(Environment.GetEnvironmentVariable("GITHUB_ACTIONS")))
{
    try
    {
        builder.Configuration.AddAzureKeyVault(vaultUri, new DefaultAzureCredential());
    }
    catch (Azure.Identity.CredentialUnavailableException)
    {
        // no creds available (e.g. CI), skip Key Vault
    }
}

C) Accessing your new secret in code

1. Inject IConfiguration into any class (controller, service, etc.):
   public class MyService
   {
     private readonly string _newApiKey;
     public MyService(IConfiguration config)
     {
       _newApiKey = config["MY-NEW-API-KEY"];
       if (string.IsNullOrWhiteSpace(_newApiKey))
         throw new InvalidOperationException("MY-NEW-API-KEY is missing!");
     }
   }

2. Use _newApiKey exactly as needed.

D) Local development

- Log in to Azure CLI:
  az login
- Or set AZURE_CLIENT_ID, AZURE_TENANT_ID, AZURE_CLIENT_SECRET (e.g. in devcontainer env-vars).
- Run dotnet run; DefaultAzureCredential will fetch your vault secrets.

E) CI / GitHub Actions

- Because GITHUB_ACTIONS is defined, the guard skips AddAzureKeyVault.
- dotnet ef, build, publish run without needing Azure credentials.
- No changes required in your workflow YAML.

Summary

1. Azure: Create secret + grant managed identity
2. Program.cs: Register Key Vault with CI-skip guard (once)
3. Code: Read builder.Configuration["SECRET_NAME"]
4. Local: az login (or SP env-vars) for DefaultAzureCredential
5. CI: nothing extra—builds succeed without credentials
